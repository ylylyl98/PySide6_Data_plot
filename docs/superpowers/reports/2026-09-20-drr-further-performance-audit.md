# DRR 后续性能审查

日期：2026-09-20。范围：目录发现、文件选择、External 匹配、加载、绘图、PNG/DAT 导出。此次没有修改应用行为；新增独立测量脚本。所有导出测试使用临时目录，源数据未修改。

## 测量边界

数据目录 YZ365，631 个目录条目，选定 1 个 measurement、3 个 background，矩阵 157 × 1340。独立脚本 `artifacts/audit_drr_hotpaths.py` 的普通计时与 cProfile 分开运行；cProfile 会显著放大 Python 循环开销，其耗时不能作为用户等待时间或预计节省时间。GUI worker 内的实验 profile 出现跨线程计数异常，未用于结论；这里使用单线程独立 profile 验证调用热点。

两次独立进程试验：目录重复加载 0.913/0.831 秒；单独 JSON 读取还原 0.784/0.983 秒；External 首次匹配 2.017/1.928 秒，重复匹配 0.458/0.437 秒。系统磁盘缓存未清空，数值有波动，不应把不同调用的时间相减当成严格分解。

先前无 profiler 的完整分阶段测量仍保留于 `artifacts/current-drr-workflow-timing.json`：首轮合计 5.176 秒、第二轮 3.164 秒。包括目录、打开选择器、匹配、加载、raw/second 显示以及 2 PNG + 2 DAT；不含启动、人工操作和导出后的历史状态刷新。此次未声称已缩短该总时间。

## 1. 优先：JSON 持久缓存之上增加内存快照，并去重光谱网格

位置：`core/source_catalog_cache.py:108`、`core/drr_catalog.py:38`。

每次 load_drr_catalog 都重新创建缓存对象，缓存命中仍读取并递归还原完整 JSON。当前历史目录快照 15,848,232 字节；631 条来源中只有 5 套不同的 spectral_grid，却重复存储 845,540 个网格数值。按完整元组去重后只需 6,700 个数值，网格数值数量减少约 99.2%，这不等于整个 JSON 会缩小 99.2%。profile 确认 _decode 约 128 万次调用。

建议：保留 JSON，进程内用有容量限制的已解码快照；磁盘 JSON 使用共享 grid 表 + 每条来源的 grid id。网格按完整数值比较去重，不舍入。schema 升级，旧缓存可读取或安全重建。历史覆盖层优先只存角色/已处理状态，避免再次复制原始光谱描述。

正确性：目录身份、include_all、schema、文件变化代次均进入缓存键；仍异步校验目录清单。共享记录不可被调用方原地修改。不能以永久跳过磁盘校验换速度。

## 2. 优先：External 先验证已有配方，再搜全目录

位置：`core/drr_auto_external.py:15`、`core/drr_sources.py:929`。

当前先遍历候选来源，再读取/尝试保存过的配方。此样本最终只用 3 个背景，但 profile 记录 inspected 634 次，Path.resolve 2,653 次。resolve_drr_background_assignments 还会重新为所有历史配方建立 measurement 索引。

建议：历史配方按 measurement 身份维护索引；先检查所选 measurement 与配方中的全部 backgrounds，失效或不存在时才构造/检查推荐候选集。一次请求内复用规范化路径，避免重复调用 Windows 路径解析。

正确性：保持显式用户选择优先、全部背景成员、严格光谱网格匹配及历史冲突处理；不能只加载背景组第一项。新文件或背景删除后必须回退重新匹配。

## 3. 优先：相同目录发布不应清空选择器缓存

位置：`ui_qt/controllers_drr.py:1403`、`:1828`。

_apply_catalog_preview 先调用 _catalog_groups，然后才判断分组是否相同；_catalog_groups 已经清空文件/分组行缓存，并重建路径索引、分组及背景推荐。因此相同的 preview/completion 虽然不重绘，仍有主线程工作和后续缓存失效。

建议：先判断来源代次、过滤条件及推荐依赖是否变化；相同发布直接返回。变化时只失效受影响的分组。_drr_scroll_anchor 还从第 0 行逐项查矩形，可用视口顶端 indexAt 加回退；不保留视图时不查锚点。

收益尚未单独量化。此项直接针对交互主线程，优先于继续增加后台线程。保留现有动态换行行高与 JSON 行高缓存，验证窄窗口、100%/150% DPI、滚动及长文件名截图。

## 4. 优先：文件监控定向失效和覆盖兜底

位置：`ui_qt/main_window.py:1073`、`:1173`。

任意被接受的目录事件会清空所有模式的 ready 状态，并拆除再建立全部 watcher。递归监控只加入最多 256 个目录，不能据此保证更深/更多目录的新文件一定立即出现；尚未在此数据集复现漏报。

建议：按变化路径区分原始数据、DRR 历史及其他模式，仅标记相关缓存过期。原目录未变时保留 watcher，只对新增/删除目录增减。对未覆盖目录和 watcher 失败，在打开选择器时异步做轻量清单校验；先显示缓存，变化后增量发布。事件防抖与写入完成重试需同时保留。

## 5. 次优先：历史元数据逐文件更新

位置：`core/drr_sources.py:642`。

_read_drr_metadata 会检查全部 metadata 和路径依赖；任何一项变化后重新解析全部历史。require_drr_operation 的两个缓存键也各存一套解析结果。导出越多，代价越明显。

建议：按 metadata 路径及签名缓存单文件解析结果，新增/删除/变化只更新对应记录。基础解析共享，再派生严格/兼容视图。建立 source 到受影响配方的依赖索引，保持移动、删除、外部编辑与损坏 JSON 的恢复行为。

## 6. 次优先：成对导出共用历史索引快照

位置：`core/export.py:772`、`:830`。

Raw 和 d2E 各调用一次 _existing_drr_result；当 preferred_stem 未命中时，各自读取/检查完整导出索引。此前普通计时冷索引检查约 1.175 秒，热态每产品约 0.06 秒。

建议：一次 pair export 复用已验证的目录/索引快照，写入 Raw 后将新增记录更新到本次快照，再供 d2E 使用。外部并发导出与索引原子更新需要防止丢记录。首次索引可在目录空闲时预热，但避免与用户加载争抢 I/O。

## 7. 后续：精确保留衍生结果，按证据再优化渲染

_on_loaded（`ui_qt/main_window.py:6306`）始终清空导数缓存，即使底层数据可复用。可考虑以完整数据/背景/SG 参数签名保留少量结果，但必须包含数据版本，不能仅按文件名判断。先分别测导数计算与 Matplotlib 重绘；当前 second 阶段约 0.5 秒包含两者，不能全部归因于计算。

普通热态 pair export 约 0.813 秒，其中 PNG 渲染约 0.48 秒、DAT 约 0.19 秒。降低 DPI、数值精度或更换 DAT 格式不建议作为默认优化。进程隔离渲染可能改善 GUI 抖动，但启动和数据传输成本未量化，适合后续 A/B 验证，不宜直接承诺更快。

## 建议实施与验收顺序

先做 1–4，再做 5–6，最后评估 7。优先保证新文件可见、完整背景组和导出数值一致。验收覆盖冷启动/热态、目录无变化/新增/删除/修改、导出后历史更新、大量子目录、长文件名/DPI 截图、后台计算期间交互最大间隔。收益必须重跑无 profiler 工作流测量，不能把各条理论节省简单相加。
