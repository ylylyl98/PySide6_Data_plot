# DRR 缓存和刷新优化结果

已实施 2026-09-20 性能审查中的目录缓存、External 匹配、选择器重复刷新、文件监控、历史增量解析和成对导出索引复用。没有降低 PNG 清晰度或 DAT 数值精度。

## 实现

- `core/source_catalog_cache.py`：schema 2 JSON 按完整数值去重 spectral_grid，旧 schema 自动迁移；最多 4 份 DRR 内存快照，缓存文件签名变化即失效。返回独立来源列表，继续校验目录清单；JSON 保留为持久化格式。
- `core/drr_auto_external.py`：先验证已保存的完整背景配方，无有效配方时才创建全目录候选集。请求内复用路径和 measurement→recipe 索引。
- `ui_qt/controllers_drr.py`：同来源/过滤条件的发布不重新分组和清空行缓存；不保留视图时不查滚动锚点，保留视图时优先定位视口顶部行。打开选择器后异步验证目录。
- `ui_qt/main_window.py`：同目录保留 watcher；MCD/DRR 历史事件定向失效；容量满时优先保障关键目录。选择器自动验证使用 catalog_only，刷新列表但不扩大已选组、匹配或 Load；手动完整刷新在合并请求中优先。
- `core/drr_sources.py`：按文件签名和来源依赖缓存历史关联，修改一个文件只重新解析该文件；严格/兼容视图共享解析；同一扫描共享路径解析，同时保留逐文件依赖和扫描后的变化检查。
- `core/export.py`：Raw/d2E 复用本次导出的索引 JSON 快照；继续逐项验证元数据签名，检测新增、删除和外部修改。仍保留原子写入。

## 实测

相同 YZ365 数据：631 个目录条目、1 个 measurement、3 个完整背景成员，矩阵 157 × 1340，每轮实际输出 2 PNG + 2 DAT 到临时目录。

| 阶段 | 改前第二轮 | 改后第二轮 |
|---|---:|---:|
| 目录加载/验证 | 0.935 s | 0.136 s |
| 选择器打开 | 0.158 s | 0.139 s |
| External 匹配 | 0.438 s | 0.234 s |
| 数据加载 | 0.044 s | 0.048 s |
| Raw 显示 | 0.226 s | 0.336 s |
| Second 计算和显示 | 0.550 s | 0.519 s |
| 成对导出 | 0.813 s | 0.786 s |
| 分阶段合计 | **3.164 s** | **2.198 s** |

热态合计缩短约 30.5%。首次进程内工作流从 5.176 s 到 5.177 s，基本相同；首次历史检查和输出索引构建仍占较多时间。一次旧缓存迁移有额外解析和写入开销，不代表后续启动耗时。

目录 JSON 从 15,848,232 字节缩至 7,560,115 字节，约减少 52.3%。631 个文件的 845,540 个重复光谱网格数值改为共享 5 套、6,700 个数值。其他描述字段仍保留。

计时使用无 profiler 的实际 worker 和 Qt 离屏显示。系统磁盘缓存未清空，数据不是多轮统计分布；合计不包含应用启动、人工操作及导出后的历史状态刷新。新版本包含打开选择器后的异步校验，与后续步骤可重叠；这是实际新增行为，不应把各项节省简单相加。科学渲染存在波动，首次运行未声称提速。

原始数据：`artifacts/drr-workflow-before-cache-refresh.json`、`artifacts/current-drr-workflow-timing.json`、`artifacts/drr-hotpath-audit/timings.json`。

## 验证

最终相关 unittest 合计 **221 项通过**（40.220 秒），包括 DRR 来源、数值背景处理、推荐、目录、选择器和导出套件。测试中的空切片/退化坐标轴警告来自对应边界数据用例，无测试失败。

覆盖缓存迁移与文件替换、容器隔离、完整背景组、历史修改/新增/删除、来源移动、刷新请求合并、新文件在取消选择器后仍可发布、取消不改变已选项或触发 Load、监控容量满时关键目录优先、导出索引外部修改检测及数值工作流。

长文件名检查使用 720 个合成来源、240 个分组，920/1120/1300 宽度，100% 和 150% 缩放。每种缩放采样 32 个绘制行，行高不足数量均为 0；人工查看窄窗口截图，完整行的 `_END.csv` 尾部可见。视口底部的部分可见行仍通过正常滚动查看。

截图：`artifacts/drr-picker-layout-check/narrow-scale-1.5.png`。行高缓存仍写入原有 JSON。

独立代码复查发现的自动验证引发 Load、满容量监控丢失关键目录两项问题均已修复并补回归。此次没有实施降低渲染质量、跨进程绘图或衍生数据缓存生命周期重构。
