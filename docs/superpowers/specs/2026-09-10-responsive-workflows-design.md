# 更简洁、跟手的工作流：审查与交互设计

日期：2026-09-10。用户要求本轮只提出 plan，不实施。已有文件选择可靠性及 Rot1/Rot2 改动保持原样。

## 目标

用户确认有效输入后自动获得图；连续选文件或调参数时，以最后一次有效意图为准；加载、扫描、计算不阻塞操作。统一页面的操作顺序和反馈方式，而不是把所有数据选择器做成一样。

## 审查依据与限制

本轮检查当前代码中的选择、信号、加载、计算、绘图和目录刷新链路。未测量真实数据的耗时，下面的同步路径是已确认的性能风险，不代表已测得某个页面卡顿多少毫秒。

两项不改文件的最小调用验证：

- `_start_load` 在 `_load_in_progress=True` 时只输出 `Load already in progress`，没有登记后续请求。
- `ShgController._on_shg_source_changed` 在 `loaded=None` 时不发起加载。

直接导入主窗口曾遇到上轮已知的 QtCore DLL 问题；先导入 QtCore 后完成上述调用验证。此问题不混入本轮交互改造，性能测试应记录启动方式和环境。

## 已确认的交互/性能问题与代码证据

行号按本轮审查时记录，执行时以函数名为准。

1. **首次自动加载不一致**：`ui_qt/controllers_compare.py::_cmp_open_group_dialog`（约 328–348）与 `controllers_shg.py::_on_shg_source_changed/_on_shg_workflow_changed`（约 270–281）。PL 对照：`controllers_pl.py::_edit_pl_source/_open_pl_saved_results`（约 352–373）。
2. **忙碌时请求丢失**：`ui_qt/main_window.py::_start_load`（3400–3406）立即返回；`_on_load_finished`（4222）有 MCD 专用重试，但没有所有工作流共用的“最新请求”。`_on_loaded`（4034）结果代次校验主要针对 MCD；其他页切源/切目录/切页时的过期结果需要补实际回归。
3. **加载成功已自动绘图**：`main_window.py::_on_loaded`（约 4196–4211）调用 `_plot_mode(..., auto=True)`。主要缺口在前段触发和请求调度，不能笼统说全应用都要再点 Plot。
4. **绘图路径中同步读文件**：`main_window.py::_plot_mode`（6304）调用 `_ensure_loaded_matches_ui_params`（4742），后者直接调用 PL/Compare/Power loader；DRR 的 `_ensure_loaded_matches_drr_params`（7055）也可同步读文件。必须把输入/处理变化与纯显示变化分开。
5. **Power 重复状态扫描**：`controllers_power.py::_power_refresh_groups`（约 403–409）在组成员循环里调用 `processed_source_names(folder)`；`core/power_workflow.py::processed_source_names`（176）扫描/读 metadata。应一次目录批次算一次，而不是按组/成员重复。
6. **后台扫描结束后仍有 GUI 工作**：`main_window.py::_on_file_lists_result`（约 2854）调用 Compare history 扫描和 Power 组刷新；`controllers_compare.py::_cmp_refresh_history_cache`（164）递归读 JSON。后台完成不代表 GUI 发布阶段轻量。
7. **Power 确认按钮同步验证**：`ui_qt/power_group_dialog.py::_validate`（317–332）在确认回调中调用完整加载；`_power_candidate_files` 也会重新发现文件。缓存冷启动时需要 worker。
8. **部分开销在防抖之前**：PL/DRR/Compare 参数回调先 `_refresh_automatic_ranges`，然后 `_schedule_plot_redraw`；90 ms 合并仅覆盖后段。Power 已将部分范围刷新移入合并回调，可作为局部参考。
9. **广泛重建画布**：`main_window.py::_plot_mode`（约 6325）一般 `figure.clear()` 重建 axes。DRR gate、Power gate 和 MCD 已有局部更新路径，应扩展而不是推倒重来。
10. **已有异步防护不等于资源合并**：SHG 有 100 ms 防抖及 generation 检查，但每次到期可能再提交 worker，旧工作不一定停止消耗资源。需验证快速连续修改时队列长度和旧结果丢弃。
11. **跨页状态不对称**：主窗口主要保存一个 `self.loaded`；切页特殊处理 DRR，其他页需核对缓存恢复和旧图所属页面。先修“图与当前页不匹配”，再按数据规模决定有限缓存。

## 统一的用户规则

### 常用路径

`选择数据 → 输入完整性确认 → 后台加载/处理 → 自动显示 → 调整视图 → 显式导出`

- 文件弹窗中单击只预选和看详情；双击或主按钮“打开并显示”提交，避免方向键浏览就加载大文件。
- 直接显示在页面上的单文件选择，稳定停留约 150 ms 后提交；多角色表单完成一组有效输入后提交一次。
- 无效或未完整的输入显示就地提示，不连续弹模态错误框，不猜测替换角色。
- Load 不再是必经步骤，改为次要的“重新加载”；自动更新开关默认开，用于暂停昂贵处理，不能用它掩盖忙碌时丢请求。
- Plot/Update 不再是普通改参数后的必经步骤。处理暂停时保留“立即更新”；拟合、Combine、批处理、导出保持显式操作。
- 扫描目录不等于换数据。Refresh 只更新目录和历史；当前选中源确有变化时才触发符合现有规则的重载。

### 页面布局

相同层级顺序：`数据 → 常用显示 → 分析 → 高级`。这不是统一控件类型。

- 数据区：当前文件/组摘要、选择、清除、可展开角色/背景明细；处理历史是辅助信息，不覆盖当前所选名称。
- 常用显示：当前视图、常用坐标/色阶、Auto/Fix；默认显示高频选项。
- 分析：工作流专属操作，结果状态就近展示。
- 高级：背景细节、角度规则、拟合初值、导出选项按任务折叠；折叠不能重置参数。
- 记住每页展开状态；不增加向导、步骤页或更多确认。
- 自动更新时保留上一张有效图并标“正在更新到 B”；图注明实际已显示的数据 A。失败时明确“仍显示 A”，禁止将 A 当作 B 导出。
- 切页恢复该页视图/选中状态；不能让其他页迟到的结果抢走当前图。

## 调度与性能约束

- 按工作流维护最新请求版本、文件夹身份、源/角色快照、处理参数快照；GUI 线程采集参数，worker 不读取 Qt 控件。
- 一个有界计算通道中保留当前工作和最后一个待执行请求。新请求取代旧 pending；过期结果/错误不得覆盖新选择或状态。不能安全中断的任务允许算完并丢弃，不能强杀线程。
- MCD 的稳定性等待及现有 pending/generation 机制逐步接入，避免新旧调度各发一次请求。
- 纯视图变化不读 CSV、不扫描目录、不重拟合；处理变化在 worker 对已有原始数据计算；源变化才重新读文件。
- GUI 仅发布结果和更新 Matplotlib artists；Matplotlib/Qt 对象不能搬到 worker。
- 目录/历史缓存按 folder、扫描代次、mtime/size 或已知导出事件失效。不为性能牺牲同名文件身份、未知状态、缺失文件和 queued Refresh 修复。
- 跨页缓存限量、统计内存；MCD/Peak Shift 共用数据，避免副本。容量在实测后设定，不预设可缓存任意数量的大矩阵。

## 待测指标与验收目标

以下为目标，不是本轮已测数据：操作后约 50 ms 内出现反馈；缓存命中的光标/曲线更新 p95 约 100 ms 内；普通绘图选项停止输入后约 200 ms 内显示（复杂图实测后单列预算）；繁忙时事件循环心跳 p95 延迟不超过 50 ms、p99 不超过 150 ms。冷文件加载耗时单独报告，不承诺任意文件 200 ms 处理完成。

测量从用户事件到 paint/draw 完成，而不是只量 worker：selection→enqueue、queue wait、read、compute、publish、first draw。用当前真实小/中/大数据以及 100/1000/5000 条目录与 1000 个历史记录作基准；记录硬件、输入大小、冷/热缓存、重复次数、p50/p95。

## 本轮不做

不修改代码或测试，不启动实施，不改分析算法/默认科学参数，不自动导出，不移除专业工作流，不重构成新 GUI 框架。不将已有 Qt 测试环境问题误报为此次性能测量结果。
