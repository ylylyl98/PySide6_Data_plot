# Independent Peak Analysis window

The user approved integrating the illustrated layout, with all production UI in English. The plot toolbar opens a native Qt window in a separate process. Its heatmap and linked spectrum dominate the page; a compact right panel holds range, detection, persistent named branches, tracking and optional PL fits. Progress is inline. Results and export are explicit actions; no log/results dock opens automatically through this workflow.

PL and DRR have separate algorithm adapters. Shared snapshot, branch, plotting, export and window code avoid four duplicate pages. Compare and Power Dependent send their displayed intensity channels to the PL adapter. VP is excluded. DRR sends each actual displayed product as a distinctly named dataset, preserving derivative provenance and avoiding a second derivative calculation on already processed data.

Analysis uses linear numeric intensities, independent of display normalization. Multiple manually chosen or automatically detected seeds retain IDs and colors. Tracking leaves gaps at absent or ambiguous extrema. PL multi-peak Gaussian/Lorentzian fits use detected centers and retain failure diagnostics. Detected extrema and fitted centers remain separate.

Data snapshots and results use atomic, pickle-free persistence. Content identity includes source, channel, axis metadata and numeric arrays. Applying an overlay checks current identity; stale results cannot attach to changed data. Plot-only changes do not trigger analysis. Snapshot preparation and hashing run outside the app GUI thread. Background analysis, cancellation and bounded concurrency preserve responsiveness.

Closing and reopening the analysis process reloads source code while the app stays open. Restart Analysis saves state before launching a fresh process. Initial toolbar integration needs one app restart. Frozen builds support launching/restarting the child but require rebuilding to change bundled code. The first version must not claim live EXE hot reload.

Existing DRR workspace and Power trend tools remain available. Existing uncommitted source changes are preserved. No web runtime is added to the desktop app.

Product-specific recommendation: the current default for new PL/intensity and raw ΔR/R snapshots is SG + extrema (11 samples); derivative products start with Local extrema to avoid extra smoothing. This refines the earlier universal SG default. The description explains the recommendation without overriding an explicit choice. The child process applies current recommendations on fresh, unanalysed app handoffs; workspace restoration and reimport of an existing dataset preserve its settings, candidates and results. Therefore this defaults/UI update only requires Restart Analysis in a source deployment.

Acceptance: numerical tests for multiple peak/dip identity and PL fits; persistence round trips and stale result rejection; real child-process reopen with saved state; toolbar handoff and overlay behavior; native window interaction, light/dark, compact layout, no automatic dock opening.

Current quality defaults supersede the older 5% prominence-only policy below. The approved Balanced / Sensitive / Strict buttons select reversible shape, SNR and same-polarity neighboring-row filters before branch association. Balanced starts at SNR 5, support 3/5, prominence 0.10, minimum half-prominence width 1 meV, spacing 2 meV. Sensitive uses 3, 2/5, 0.05, 0.5 meV; Strict uses 7, 4/5, 0.15, 1.5 meV. Presets clear maximum width/count caps and preserve detector, range and polarity. Manual changes indicate Custom filters. Acquisition floor/SG controls are in Detection options; SNR, width and support remain prominent, with supplementary filters in More filters.

Noise metrics are cached once per detector pool: detection-signal residual after an order-2 SG baseline (up to 51 samples), robust MAD / 0.67448975, separately over finite energy segments. This estimates noise only; it does not change detected coordinates or widths. SNR is a heuristic prominence/noise ratio, not a confidence probability. Missing estimates for segments under 7 samples fail an enabled SNR filter. Support uses up to five sorted scan rows, after shape/SNR checks and before range cropping, with 1.5 meV drift tolerance per neighboring row. Edge requirements scale with available rows; large scan gaps break support; a single spectrum needs no absent neighbors. Old caches are enriched atomically in a background worker without rerunning detection. Saved results/settings are not silently refiltered on restore. IDs/colors/manual branches remain persistent. Results and exports carry noise/SNR/support evidence.
